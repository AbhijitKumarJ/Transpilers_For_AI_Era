# PythonSharp Language Server (`psc lsp`)

PythonSharp includes a pure-Python, zero-dependency Language Server Protocol (LSP) server implementing JSON-RPC 2.0 over standard input and output (`stdio`).

The server provides real-time compiler diagnostics, type hover cards, go-to-definition navigation, and keyword/symbol autocompletion across any LSP-compliant editor.

---

## 1. Starting the Server

The server is integrated directly into the `psc` CLI:

```bash
psc lsp
```

No external NodeJS or Python wrapper is required. The server reads `Content-Length:` framed JSON-RPC 2.0 packets on `stdin` and writes responses and notifications to `stdout`.

---

## 2. Supported Capabilities

| Capability | LSP Method | Description |
| :--- | :--- | :--- |
| **Document Sync** | `textDocument/didOpen`, `didChange`, `didClose` | Full-document synchronization and live parsing across `.ps`, `.pysharp`, and `.pys` files |
| **Diagnostics** | `textDocument/publishDiagnostics` | Real-time compiler diagnostics (`PS000`–`PS005`) with exact source spans and actionable fix hints |
| **Hover Cards** | `textDocument/hover` | Type signatures, class/interface/record declarations, docstrings, Core type documentation, and interactive Tri-Modal Surface Ladder badges |
| **Go To Definition** | `textDocument/definition` | Navigates to symbols within the current document, cross-file declarations across the workspace/project, and ambient standard library stubs (`PythonSharp.Core.d.ps`) |
| **Completion** | `textDocument/completion` | Autocompletes C# keywords, namespaces, project symbols, and Core standard library types (`String`, `List`, `Dict`, `Task`, `IEnumerable`, `Console`, `Math`, `Int32`, etc.) |
| **Document Formatting** | `textDocument/formatting` | In-editor code formatting (Shift+Alt+F / Format Document) applying standard Allman brace style and token preservation |

### 2.1 Tri-Modal Surface Ladder Hover Cards

When hovering on any type or member symbol from ambient bindings (`stdlib/01_python_stdlib/`, `stdlib/02_scientific_and_ai/`, or generated by `psc bindgen --triple-surface`), the LSP server automatically detects the symbol's `[SurfaceLevel]` and `[CanonicalApi]` metadata and appends an informative surface card:

```markdown
```csharp
(method) NDArray<double> np.ones(int rows, int cols)
```
*Declared in `stdlib/02_scientific_and_ai/01_numpy/01_numpy.raw.d.ps`*

---
**Surface Tier:** `Surface 1 (Raw ABI — Python-native snake_case)`
**Canonical Target:** `PythonSharp.Numerics.Creation.ArrayFactory.CreateOnesMatrix`
```

This gives developers instant inline feedback on where their code sits on the tri-modal ladder and guides them toward enterprise-grade canonical APIs without leaving their editor.

### 2.2 Ambient Stub Resolution in Installed Environments

The LSP server locates ambient definition stubs via `_find_default_stdlib_dir()`. In a packaged wheel installation, all 95 standard library stubs (`00_core/`, `01_python_stdlib/`, `02_scientific_and_ai/`) are packaged directly inside `site-packages/psc/stdlib/`.

When initialized in any editor workspace:
1. `psc lsp` scans its own package directory (`Path(__file__).resolve().parent / "stdlib"`).
2. It ingests all ambient `.d.ps` definitions into its root symbol table (filtered dynamically by `.ps.conf.json` if present).
3. **Go To Definition (`F12`)** on types like `ArrayFactory`, `NDArray`, `DataFrame`, `Task`, `List`, or `Console` immediately resolves to the corresponding `.d.ps` file in `site-packages/psc/stdlib/`.
4. IntelliSense autocompletions and hover documentation work without needing access to the compiler repository or source checkout.

### 2.3 Precision Go-To-Definition (`F12`) & Member vs. Namespace Priority

In C# and PythonSharp, identifiers can occasionally collide with package or namespace names (e.g., `Pyplot.Legend(...)` invoking a method on `Pyplot`, where a `namespace PythonSharp.Primitives.Matplotlib.Legend` also exists in the project or dedicated stubs).

The Language Server implements strict priority resolution to ensure intuitive navigation:
1. **Half-Open Column Span Matching:** When clicking an identifier, the token finder uses `start_col <= col < end_col` priority. This ensures that clicking on the first letter of a member right after a dot (`.Legend`) targets the member identifier, rather than the preceding dot token (`.`).
2. **Member Over Namespace Priority:** In invocations or member access chains (`Target.Member`), if `Target` resolves to a known type (e.g., static class `Pyplot`), `psc lsp` searches exclusively for `Member` within that type and its base types. It will never fall back to matching unrelated top-level classes or namespace tokens in the global symbol table.
3. **Cursor-Scoped Namespace Navigation:** A namespace token is only resolved as a namespace declaration if the cursor is explicitly on the file's `namespace` statement span; in all expression positions, member and type lookups take complete precedence.

## 3. Dynamic Stub Layer Configuration (`.ps.conf.json`)

To prevent Intellisense pollution and symbol collisions across broad ecosystems, `psc lsp` dynamically respects project-level configuration files (`.ps.conf.json`, `psconfig.json`, or `pythonsharp.json`):

```json
{
  "stub_layers": {
    "00_core": true,
    "01_python_stdlib": true,
    "02_scientific_and_ai": false,
    "03_typeshed_replica": false,
    "dedicated_stubs": true
  },
  "disabled_packages": [
    "matplotlib",
    "pandas"
  ],
  "preferred_surface": 2
}
```

### Configuration Behaviors:
- **`stub_layers`:** Enables or disables entire standard library or external layers. Disabling `02_scientific_and_ai` ensures that built-in scientific stubs do not conflict when generating dedicated library stubs via `psc stubgen`.
- **`disabled_packages`:** Selectively deactivates specific ambient packages from compiler stdlib ingestion.
- **`preferred_surface` (`0`, `1`, `2`, or `3`):** When set to a surface tier (e.g. `2` for Surface 2 Idiomatic Bridge), the LSP loads only Surface 0 (primitives) and Surface 2 (`*.csharp.d.ps`) stubs from `.ps-stubs/`, completely ignoring Surface 1 (`*.raw.d.ps`) and Surface 3 (`*.enterprise.d.ps`). This cuts symbol index size in half and guarantees Go-To-Definition jumps directly to your idiomatic C# API.

## 4. Editor Configurations

### Visual Studio Code
A ready-to-use extension is provided in `editors/vscode/`. It contributes syntax highlighting, language configuration, file associations (`*.ps`, `*.pysharp`, `*.pys`, `*.d.ps`, `*.d.pysharp`, `*.d.pys`), and automated LSP client management (`psc lsp`).

#### Installing the Extension
You can install the packaged `.vsix` extension or link the development folder:

```bash
# Option 1: Install the pre-built VSIX package
code --install-extension editors/vscode/pythonsharp-0.1.0.vsix

# Option 2: Link into your local extensions directory for development
mkdir -p ~/.vscode/extensions
ln -s $(pwd)/editors/vscode ~/.vscode/extensions/pythonsharp
```

#### Commands in VS Code Command Palette
The extension registers all `psc` compiler operations directly into the VS Code Command Palette (`Ctrl+Shift+P` / `Cmd+Shift+P`):

- **PythonSharp: Build Project (`psc build`)**: Builds the current project and its referenced dependencies.
- **PythonSharp: Rebuild Project (`psc rebuild`)**: Cleans output and rebuilds from scratch.
- **PythonSharp: Clean Output (`psc clean`)**: Cleans the build directory and cache files.
- **PythonSharp: Check Diagnostics (`psc check`)**: Validates syntax and semantic types without generating files.
- **PythonSharp: Run Project / Entrypoint (`psc run`)**: Compiles and runs the static `Main` entrypoint.
- **PythonSharp: Watch Project for Changes (`psc watch`)**: Starts continuous incremental compilation on change.
- **PythonSharp: Format Document (`psc format`)**: Formats the active `.ps` document using LSP or CLI.
- **PythonSharp: Create New Project (`psc create`)**: Interactively prompts for a project name and scaffolds a starter project.
- **PythonSharp: Add Project Reference (`psc add reference`)**: Selects or inputs a referenced `.psproj` to add to the active project.
- **PythonSharp: Dump Lowered AST (`psc dump-ast`)**: Dumps lowered Python source code to the terminal.
- **PythonSharp: Generate Stubs from Python (`psc bindgen`)**: Prompts for a Python package name and generates `.d.ps` ambient stubs.
- **PythonSharp: Restart Language Server**: Gracefully reloads the language server and refreshes diagnostics.

Clicking the **$(zap) PythonSharp** status bar icon opens a quick-pick menu of these commands.

#### Manual Configuration
To configure manually via the generic `vscode-languageclient` or standard runner:
```json
{
  "pythonsharp.serverPath": "psc",
  "pythonsharp.serverArgs": ["lsp"]
}
```

### Neovim (Built-in LSP)
Add the following to your `init.lua` or `after/ftplugin/pythonsharp.lua`:

```lua
vim.filetype.add({
  extension = {
    ps = "pythonsharp",
    pysharp = "pythonsharp",
    pys = "pythonsharp",
  },
})

local client = vim.lsp.start({
  name = "pythonsharp-lsp",
  cmd = { "psc", "lsp" },
  root_dir = vim.fs.dirname(vim.fs.find({ "*.psproj", "*.pysharpproj", ".git" }, { upward = true })[1]),
})
```

### Helix (`languages.toml`)
Add to `~/.config/helix/languages.toml`:

```toml
[[language]]
name = "pythonsharp"
scope = "source.ps"
file-types = ["ps", "pysharp", "pys", "d.ps", "d.pysharp", "d.pys"]
roots = ["*.psproj", "*.pysharpproj", ".git"]
language-servers = ["psc-lsp"]

[language-server.psc-lsp]
command = "psc"
args = ["lsp"]
```

### Sublime Text (LSP package)
In `LSP.sublime-settings`:

```json
{
  "clients": {
    "pythonsharp": {
      "enabled": true,
      "command": ["psc", "lsp"],
      "selector": "source.ps, source.pysharp, source.pys"
    }
  }
}
```
