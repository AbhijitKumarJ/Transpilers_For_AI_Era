## 1. The Mathematics: Why $6k \pm 1$ Trial Division?

The naive way to test if a number $n$ is prime is to check if it is divisible by every number up to $n-1$, which takes $O(n)$ time.

A standard optimization is to check divisors only up to $\sqrt{n}$, since any factor greater than $\sqrt{n}$ must be paired with one smaller than $\sqrt{n}$.

The **$6k \pm 1$ optimization** goes one step further:
- All primes greater than 3 can be written in the form $6k + 1$ or $6k - 1$ (i.e. $6k \pm 1$), where $k \in \mathbb{N}$.
- Why? Any integer can be expressed as $6k$, $6k+1$, $6k+2$, $6k+3$, $6k+4$, or $6k+5$.
  - $6k$, $6k+2$, and $6k+4$ are divisible by 2.
  - $6k+3$ is divisible by 3.
  - Only $6k+1$ and $6k+5$ (which is $6(k+1)-1$) can be prime!

By testing 2 and 3 upfront, our loop can test candidate divisors stepping by 6 ($i$ and $i+2$), eliminating $\frac{2}{3}$ of all division checks!

## 3. The C# Source Implementation: `PrimeMath.ps`

[`PrimeMath.ps`](file:///home/abhijit/Videos/transpilers/PythonSharp/Samples/Ported/03_isprime/PrimeMath.ps) implements four core mathematical methods:

```csharp
namespace MathUtil;

using PythonSharp.Core;

public class PrimeMath
{
    public static bool IsPrime(long n)
    {
        if (n <= 1) return false;
        if (n <= 3) return true;
        if (n % 2 == 0 || n % 3 == 0) return false;

        long i = 5;
        while (i * i <= n)
        {
            if (n % i == 0 || n % (i + 2) == 0)
            {
                return false;
            }
            i += 6;
        }

        return true;
    }

    public static long NextPrime(long n)
    {
        if (n < 2) return 2;
        long candidate = n + 1;
        while (!IsPrime(candidate))
        {
            candidate += 1;
        }
        return candidate;
    }

    public static List<int> PrimesUpTo(int limit)
    {
        List<int> result = new List<int>();
        if (limit < 2) return result;

        int cur = 2;
        while (cur <= limit)
        {
            if (IsPrime(cur))
            {
                result.Add(cur);
            }
            cur += 1;
        }
        return result;
    }

    public static List<int> PrimeFactors(int n)
    {
        List<int> factors = new List<int>();
        if (n <= 1) return factors;

        int d = 2;
        int num = n;
        while (num % d == 0)
        {
            factors.Add(d);
            num = num / d;
        }

        d = 3;
        while (d * d <= num)
        {
            while (num % d == 0)
            {
                factors.Add(d);
                num = num / d;
            }
            d += 2;
        }

        if (num > 1)
        {
            factors.Add(num);
        }

        return factors;
    }
}
```

```python
        if n < 2:
            return 2
        candidate: int = n + 1
        while not PrimeMath.is_prime(candidate):
            candidate += 1
        return candidate

    @staticmethod

        result: list[int] = []
        if limit < 2:
            return result
        cur: int = 2
        while cur <= limit:
            if PrimeMath.is_prime(cur):
                result.append(cur)
            cur += 1
        return result

    @staticmethod
    def prime_factors(n: int) -> list[int]:
        factors: list[int] = []
        if n <= 1:
            return factors
        d: int = 2
        num: int = n
        while num % d == 0:
            factors.append(d)
            num = num // d
        d = 3
        while d * d <= num:
            while num % d == 0:
                factors.append(d)
                num = num // d
            d += 2
        if num > 1:
            factors.append(num)
        return factors
```

### Compiler Insights:
1. **64-bit Integer Mapping**: In C#, `long` is a signed 64-bit integer. In Python, `int` natively supports arbitrary precision integers. `PrimitiveResolver` maps `long` $\to$ `int`, ensuring large numbers never overflow.
2. **List Instantiation**: `new List<int>()` compiles directly to `[]`.
3. **List Append**: `result.Add(cur)` compiles to `result.append(cur)`.
4. **Integer Division**: `num = num / d` lowers to `num = num // d`. If it had compiled to standard `/`, `num` would have mutated into a float, degrading performance.
